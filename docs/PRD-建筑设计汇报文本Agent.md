# 建筑设计汇报文本 Agent PRD

## 1. 产品定位

建筑设计汇报文本 Agent 是一个面向建筑设计师的任务书到汇报成稿工作台。产品把任务书、当前项目事实、已确认设计方向、页面结构、页面文案、视觉任务和云端项目存档连接成一条可追溯链路，帮助用户快速形成可编辑的 A3 横版 PDF 与 PPTX。

产品包含两条相互隔离的管线：

- **大型公共建筑管线**：面向规划、公共建筑、综合体等项目，处理场地、功能、交通、空间、立面、技术、实施和总结。
- **小型建筑/装置管线**：面向展亭、快闪、互动装置、临时建筑和小型室内项目，处理节点方向、空间体验、材料构造、互动、复用和总结。

## 2. 用户与使用场景

主要用户是建筑师、室内设计师、设计事务所和需要制作设计汇报的学生或项目团队。典型场景包括：

1. 上传一份新任务书，快速得到项目事实和汇报骨架。
2. 检查任务书中的设计方向是否被识别，并编辑或补充方向。
3. 按页生成正文、图框标题和视觉意向图。
4. 反复修改单页或整套文案，同时保留已经生成的图片。
5. 将项目保存到云端，在刷新、换设备或再次打开项目时继续工作。
6. 导出可打印的 PDF、可编辑的 PPTX，以及文字版 DOCX 设计说明。

## 3. 产品目标

- 让新任务书成为当前项目唯一的事实来源，避免历史项目内容串入。
- 让任务书明确的设计方向优先进入页面架构；无方向时提供可编辑的设计方向候选。
- 让同一方案在概念页、效果页、构造页、对照页和总结页使用同一个方案名称与设计逻辑。
- 让正文、图片标题和图框关系适配 A3 页面，并在实际排版溢出时由模型整体重写可见文案。
- 让 AI 图片生成结果和项目内容一起保存到云端，刷新页面不丢失。
- 让生成过程可恢复、可暂停，避免重复生成已经完成的图片。

## 4. 信息边界与数据原则

### 4.1 当前项目事实

当前项目事实来自用户上传的权威任务书、当前项目方案资料和明确标注的公开场地研究。事实需要保留来源文件、页码、原文引用、来源角色和确认状态。没有来源页码与原文引用的数字、面积、预算、性能和设计结论不得写入最终事实或正文。

### 4.2 设计方向

设计方向分为两类：

- **任务书方向**：从当前任务书中优先提取，保留来源引用，作为后续页面和视觉生成的首要约束。
- **用户确认方向**：用户自行输入或确认的方向，单独保存为当前项目提案，不伪装成任务书原文；确认后贯穿页面正文、视觉提示词和总结。

任务书已有方向时，不再用空的 Gate B 模块阻塞流程。缺少方向时，Agent 可以基于任务书事实提出最多三个方向卡片，每张卡片只展示“方向标题 + 方向内容”，不展示后台字段名、变量名或序列化对象。

### 4.3 历史参考与公司信息

历史参考只提供页面结构、版式节奏和文风观察，不提供当前项目事实、设计数字、方案结论、图片或公司资料。公司名称是项目展示信息，不能进入任务书事实、历史参考或方案判断。

## 5. 核心流程

### 5.1 新建项目

1. 用户选择大型公共建筑或小型建筑/装置管线。
2. 上传任务书或粘贴文本。
3. Agent 读取 PDF、DOCX、TXT 或 Markdown 的文字与页面信息。
4. 创建当前项目资料区，清空旧项目的事实、页面、视觉任务和图片引用；历史参考区保持独立。
5. 提取项目名称、活动/项目主题、场地、功能、对象、方向、交付格式、实施条件和其他可追溯事实。
6. 生成与管线匹配的页面骨架。

### 5.2 设计方向

小型建筑/装置管线按以下优先级工作：

1. 识别任务书明确的方向、节点名称、产品/功能和互动要求。
2. 若存在明确方向，直接形成并列方向结构，不显示阻塞模块。
3. 若没有明确方向，Agent 生成最多三个不同的空间/构造方向。
4. 用户可编辑方向标题和内容。
5. 点击重新生成文案后，清除旧页面可见文案的生成状态，重新依据当前方向生成整套页面；已生成图片资产不被删除。

大型公共建筑管线允许使用目标、总体布局、交通、重点空间、立面等提案卡片，用户确认的提案进入对应页面并保留验证项。

### 5.3 页面与内容

每一页包含页面类型、章节、中文标题、英文标题、核心结论、中文正文、英文正文、图片槽、图框标题、图解标签、讲述提示、事实引用和提案引用。页面生成必须使用当前页事实与当前页相关的确认方向，不把其他方案内容带入当前页。

小型建筑/装置管线的方案名称必须由同一份当前项目方案定义提供给：

- 各方案概念页；
- 各方案主效果图页；
- 各方案构造与运营页；
- P03 或对应的方案并列对照页；
- S04 设计总结页。

总结页的图片直接复用各方案主效果图，避免重复调用模型。

### 5.4 文案与版面

- 正文建议不超过 150 个中文字符。
- 图片下方的非标题说明建议不超过 25 个中文字符。
- 这些字数是模型生成目标，不是简单截断规则。
- 初次生成先依据页面角色和布局组织短文；只有真实 A3 预览检测到文本框溢出时，才进入压缩文案流程。
- 压缩流程必须整体重写可见文案，保留完整句意和句尾，不从字符串末尾删除字符，不添加省略号。
- 小型建筑/装置专页同时约束核心结论与正文的可见总量，避免正文框和分析图重叠。
- 前端预览与 PDF 导出共用 A3 测量和自动适配逻辑；分析图无标题时，为其预留与主效果图标题带等高的底部空间，使图片下边界对齐。

### 5.5 视觉任务与 AI 图片

每个可生成图框有独立的用途、标题、简短提示词、画幅比例和当前页上下文。提示词只带入当前页和当前方案的必要信息，反向提示词保持精简。两条管线的图像模型默认使用 `gpt-image-2`。

小型建筑/装置分析图使用纯白模、线稿、黑灰细线和居中留白的表达，允许图内出现少量必要中文标签；主效果图使用当前方案的完整视觉语境。封面底图也必须进入同一视觉任务链路，不能因为它是背景而失去 AI 生成入口。

整套生图支持暂停和继续：暂停时允许当前请求完成，继续时根据项目中已保存的 `page_id + slot_id` 跳过已完成图框，只处理未完成或失败图框。

### 5.6 云端保存

MemFire 是正式项目存储。项目数据在逻辑上分为：

1. 项目基本信息：项目 ID、项目名、任务模式、公司名、文档索引和版本信息。
2. 页面内容：章节、页面结构、文案、事实引用、提案引用、视觉任务定义。
3. 图片资产：图像 URL、图片槽 ID、图片版本、生成模型、生成时间和图片状态。

自动保存只在项目内容发生变化时写入。翻页、选中图框、打开面板等纯浏览动作不写云端。图片目录清理只在删除项目、替换图片或用户手动保存时执行。图片采用长期缓存；替换图片生成新的版本 URL，不覆盖旧 URL 的读取结果。

AI 图片生成完成后必须立即把图片资产与页面引用保存到云端。重新加载项目时先读取项目内容，再按图片槽恢复已保存的图片资产；浏览器缓存只作为加速层，不作为唯一存储。

### 5.7 导出

- PDF：A3 横版，支持 144 PPI 打印导出；导出前执行页面文字与图片资源整理。
- PPTX：A3 横版，可编辑文字框，嵌入已经生成的当前项目图片。
- DOCX：生成带来源的文字版设计说明，不承载整套图片排版。

导出终稿时，如果单页模型返回超出建议字数的正文，不直接失败；系统应继续调用压缩文案流程，并以真实 A3 排版检查作为最终判定。云端任务中断时保留任务上下文，允许恢复，不生成本地替代项目覆盖云端结果。

## 6. 界面需求

- 顶部显著放置“生成整套终稿文案”“生成整套 AI 图纸”“导出 PPTX”。
- “建立整套视觉任务”不再作为用户操作按钮；视觉任务由生图流程按需建立。
- 不显示“事实就绪”“提案就绪”等容易造成误解的状态标签。
- 左侧资料栏显示任务书、项目事实、当前设计方向和公司名称；公司名称为空时显示“设计汇报 DESIGN PRESENTATION”。
- 图片槽下方只显示当前方案的可读标题，不显示“图片1设计证据”等后台占位语。
- “编辑当前页全部文字”可以编辑标题、正文、图片名称、图解标签、策略说明、章节名和项目名；英文由 Agent 根据中文生成或保持只读对应文本。
- 小型建筑/装置管线不显示无实际作用的“深度优化”入口；整套文案生成承担当前管线的重新组织任务。
- 生成任务显示当前页、当前槽位、阶段、重试状态和暂停/继续操作。

## 7. 领域契约与接口

`schemas/project_facts.schema.json` 与 `schemas/page_plan.schema.json` 是领域数据契约的唯一来源。运行时代码、API 和前端均使用生成的契约类型，不另建平行数据结构。主要动作包括：

- 运行任务书解析与页面规划；
- 生成单页或整套终稿文案；
- 创建、选择、确认或删除设计提案；
- 更新当前页视觉任务；
- 生成单张或整套 AI 图片；
- 审核整套汇报；
- 保存、加载、重命名和删除云端项目；
- 导出 PDF、PPTX 和 DOCX。

接口响应需要保留模型调用记录、图片调用记录、来源引用、可恢复错误和云端版本信息，但这些后台字段不得直接进入汇报可见文字。

## 8. 边界与后续决策

- 原生 DWG、RVT、SKP 等模型文件暂不作为任务书事实的直接解析来源。
- 结构计算、精确荷载、法规合规、精确造价和工程深化不由 Agent 代替专业校核。
- 图像模型不保证任意精确像素尺寸；系统应依据图框比例请求合适的画幅，并在必要时进行非破坏性适配或留白，而不是直接裁掉关键主体。
- 多人协同、权限、团队空间和审阅批注留待后续定义。
- 项目成果质量的评价方式、测试口径和量化指标暂不写入本 PRD，待产品方向进一步明确后补充。
