# 智能建筑汇报文本工作台

**ARCHITECTURAL REPORT INTELLIGENCE STUDIO**

一个面向建筑设计汇报工作的多项目工作台，包含“大型公共建筑”和“小型建筑/装置”两条管线。用户上传任务书后，系统先提取当前项目事实，再建立对应的页面骨架、中文正文、双语标题、视觉任务和一致性审核结果。配置 MemFire 后，项目、历史版本、生成文案和 AI 图片均保存到云端；翻页和选中图框等纯浏览动作不会触发写入。

历史参考档案只保存章节结构、页型节奏和表达风格。其项目数字、设计结论与公司信息不会进入当前项目事实或 `fact_refs`。

大型公共建筑管线使用历史页面配方、文风样本和场地研究，形成完整的建筑设计汇报结构；小型建筑/装置管线只使用当前任务书事实和已确认设计方向，按节点平行生成概念、效果、构造与复用页面，不把历史公共建筑项目带入当前项目。

## 数据契约

唯一领域契约位于仓库内：

- `schemas/project_facts.schema.json`
- `schemas/page_plan.schema.json`

`scripts/generate-contracts.mjs` 从这两份 schema 自动生成 TypeScript 类型和运行时 schema 常量。API 与前端不维护手写的平行领域类型。

## 两条管线

- **大型公共建筑**：适用于规划、公共建筑和综合体类任务书，重点处理场地、功能、交通、空间、立面、技术和设计总结。
- **小型建筑/装置**：适用于展亭、快闪、互动装置、临时建筑和小型室内项目。任务书已有方向时优先沿用；没有明确方向时，Agent 根据事实生成最多三个可编辑方向，并结合可建造性约束继续生成页面。

小型管线的三个方案名称在概念页、效果页、技术页、P03 对照页和最终设计总结页之间保持同一来源；总结页直接复用各方案主效果图，不重复调用图像模型。

## 节点顺序

1. PDF / TXT / Markdown 资料解析
2. 资料登记与角色分流
3. 建立当前项目证据区与历史参考区
4. 项目事实、冲突、缺失与设计命题提取
5. 当前项目事实与设计方向审查
6. 按管线生成页面目录和页面级证据关系
7. 用户选择一页或整套生成中文终稿文案
8. 为图框生成独立视觉任务和 AI 图片
9. 对已生成页面执行一致性审核，并在真实 A3 排版溢出时整体重写

所有节点的原始结构化输出保存在项目数据中，但不直接展示在用户端，避免历史参考配方与后台变量泄露。

## 当前执行模式

配置 `OPENAI_API_KEY` 后，工作台使用兼容 Responses API 和严格
Structured Outputs 执行六个模型节点：

- 上传后：资料登记、事实提取、完整度、Planner，共 4 次模型调用
- 用户生成一页：1 次模型调用
- 用户执行全篇审核：1 次模型调用

默认接口为 `https://ruishiglobal.com/v1`，默认文本模型为 `gpt-5.5`，图像模型固定默认为 `gpt-image-2`，可分别用
`OPENAI_BASE_URL` 和 `OPENAI_MODEL` 覆盖，也可以在网页的“API 设置”中为
当前会话临时修改。PDF 会同时提交原始
文件和分页文字层，以便模型读取页面视觉、表格和文字；最终事实仍须经过
角色隔离、页码、引用、公司信息和 schema 的本地校验。

没有密钥或模型调用失败时，系统会显式进入“本地回退”并显示原因：
角色推断、基础事实提取、两条管线的页面骨架和一致性检查仍可运行，
但不会伪装成真实模型结果。历史参考使用内置的三来源A3结构、语义标签与页型档案，
不向当前项目事实提供任何内容。

## MemFire 项目与参考库存储

1. 在 MemFire SQL 编辑器执行 `memfire/schema.sql`。
2. 在 `.env.local` 配置 `MEMFIRE_URL` 和仅供服务端使用的 `MEMFIRE_SERVICE_ROLE_KEY`。匿名密钥可以保留用于连接识别，但不会被用来读写私有项目数据。
3. 执行 `npm run memfire:reference:migrate`，将结构化参考数据和参考图片复制到私有对象存储。
4. 重启本地服务。工作台会优先读取 MemFire，并把现有浏览器项目自动迁移到云端。

未配置或暂时无法连接 MemFire 时，工作台使用浏览器 IndexedDB 临时存档，并在顶部明确显示“MemFire 未接入”。云端保存使用项目、页面和图片资产的分层更新：自动保存只提交发生变化的项目内容，AI 图片完成后单独写入图片资产；图片替换使用新版本 URL，避免刷新后丢失或误读旧缓存。

## 本地验证

```bash
npm run fixture:run
npm run fixture:brief
npm run schema:check
npm run typecheck
npm run build
node --test tests/rendered-html.test.mjs
```

完整资料虚拟项目位于 `fixtures/virtual-project/`；“系统参考 + 单任务书”回归项目位于 `fixtures/brief-only/`。两条链路的完整运行结果均写入各自的 `full-run.json`。
